# Codex 核心版：范围、安装和验收

## 2026-10-15 确认的需求

最终目标保持一体化 QA 产品，第一批交付 Codex 核心可用版，企业集成分阶段完成。
Web/API、Linux 系统软件和 AI 算力软硬件均可能成为测试对象；通过共享流程和领域
指导支持，分别声明分析设计、脚本生成和实际执行的能力。以同事项目的现有开发分支
为上游，按用户确认 Fork 到 `scienceluo/QA-Master-Skill` 独立维护，保留上游历史。
质量、覆盖、自动化、易用性、集成与成本均需评价，当前不能声称全面优于竞品。

Jira/SynapseRT、Wiki、远程测试机最终均必需；远程目标只需 Linux。暂无可用
非生产企业环境：本地可复现验证先行，真实企业联调单独验收。无固定时间或模型
预算上限，不等于无限重试或忽略已发现问题。

## 本次修复的具体问题

原 `pip install .` 只安装 Python 包；总控 Skill 未进入 Codex 的本地发现目录，
源树入口还依赖仓库内相对路径。新 `install-codex` 从安装包资源生成自包含 Skill：

- `SKILL.md`：规范入口、范围控制、专业方法选择和证据边界。
- `references/`：实际工作产物、手工确认、跨会话交接及三个领域的设计指导。
- `scripts/qa.py` 和包内运行时：可在另一项目、另一工作目录使用的本地状态助手。
- 六份原创专业指南：安装后均有实际文件可读，不依赖源码目录或其他 QA 仓库。

主入口的唯一完整来源是 `qa_master/skills/codex/SKILL.md`；原
`skills/qa-master/SKILL.md` 保留为源树兼容入口。setuptools 现有 package-data
规则包含新 Markdown 资源。安装器不读取项目凭据、不调用模型、不连接企业系统。
文件哈希清单用于检查是否可以更新，不是可信身份或生产授权证明。

安装目标依据官方 [Build skills](https://learn.chatgpt.com/docs/build-skills)
的仓库级 `.agents/skills` 与用户级 `~/.agents/skills` 规则，核对于 2026-10-15。

## 用户路径

安装后在待测项目里调用 `$qa-master`，提供需求、仓库或系统描述，说明本次任务。
Codex 读取相应指南并生成所需产物；仅在信息影响当前工作时提问。需求与用例
先由 AI 评审，再等待用户确认正式基线。开发未发布时保存 WAITING_FOR_BUILD。

用户可以要求只评审、只生成用例或恢复既有工作。交接保留实际来源与工件哈希、
已知答案、待确认问题及下一步。代码变化时核对影响，不能给旧结果换个构建标签。
本地规划 CLI 并非语义分析器，不能取代 Codex 的材料阅读和推理；它的关键字计划
不得覆盖用户明确范围。CLI 也不能认证用户身份、提交企业对象或授权测试执行。

## 验收边界

| 验证 | 支持的结论 | 不支持的结论 |
| --- | --- | --- |
| 安装、完整文件哈希和异目录运行 | 资源可用、本地助手可运行 | 模型一定会选择正确方法 |
| 状态助手暂停与范围验证 | 本地规划状态限制保持 | 完整语义任务已完成 |
| 实际 Codex 任务输出 | 对特定任务的观察 | 全领域可靠率或全面超越竞品 |
| 本地替身/接口夹具 | 已测试接口契约范围 | 真实 Jira/SynapseRT/Wiki/SSH 已联调 |

首轮场景应覆盖：仅需求且开发中、冲突需求、含缺陷源码、API/权限边界、缺失 SLA、
暂停后恢复及源版本改变。所有对比保留实际双方输出及版本，事实正确性、覆盖质量、
人工修订量、耗时和模型成本分别记录。探索性结果不作严格公平性或统计优越性证明。

安装专项和独立于源码目录的 wheel 验证已通过；实际模型行为、全量回归和竞品对比
仍待验证。具体结果及环境/远端写权限阻塞见 [验证记录](verification/codex-core-installation.md)。
本文件登记范围，不代替测试证据或完整 V1 验收。
